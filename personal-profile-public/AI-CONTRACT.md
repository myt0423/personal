# AI 读取契约（AI-CONTRACT）

> 任何 AI 接手这个仓库时，先读这一页，再动手。

## 1. 读取顺序（固定）

```text
00-identity.md
  → 01-context/work.md
  → 01-context/environment.md
  → 01-context/constraints.md
  → 04-style/writing.md
  → 04-style/decisions.md
  → 03-projects/active.md
  → 需要的部分再翻 02-knowledge/
```

**不要一次全读**。按上面的顺序读前 6 个文件就够开工，剩下的按需检索（`grep`、目录名定位）。
每次对话开头最多花 1 次工具调用在这件事上。

## 2. 在这套档案上工作时，你的行为准则

1. **不要重复问已经写在档案里的问题。** 档案里有答案就直接用；档案写"待填"才问。
2. **不要复述档案。** 你已经知道了，直接用；只在结论依赖某条具体设定时引用它。
3. **按 `04-style/writing.md` 的语感说话。** 那份文件就是我的语言指纹。
4. **遵守 `01-context/constraints.md`。** 那里写的是硬边界，不是建议。
5. **默认给可执行的东西。** 代码、命令、文件、步骤，而不是泛泛的方向性建议。

## 3. 什么时候写回档案（重要）

不要只在聊天里给结论，让它随会话蒸发。下面这些情况，**主动写回文件**：

| 触发 | 写到哪 |
| --- | --- |
| 我说了新的长期偏好 / 反感 | `04-style/` 对应文件 |
| 一个新的硬约束出现 | `01-context/constraints.md` |
| 一个项目开始 / 状态变化 / 结束 | `03-projects/active.md` / `archive.md` |
| 一次排查结束、得到了可复用的方法论 | `02-knowledge/techniques.md` |
| 我纠正了你对事实的理解 | `00-identity.md` 或对应文件 |
| 一次会话产生了重要结论 | 归纳后写进对应主题文件；**会话原文不进公开层** |
| 以上任何写入 | 同时追加一行到 `CHANGELOG.md` |

写回规则：

- **只追加和修正，不重写整篇。** 保持我的原话，除非明显有事实错误。
- 一次写回不要超过 60 行。宁可分多次。
- 改写已有内容时，保留可追溯性（在 changelog 里写明改了什么）。
- **沉淀要靠归纳，不要把对话原文成段搬进档案。**
- 涉及他人隐私、密钥、证件的信息，**不写进本仓库任何文件**，只提示我存在本地。

## 4. 事实优先级

```text
我在对话里刚说的话
  > 档案里较新的记录（看 changelog 日期）
  > 档案里较旧的记录
  > 你的先验知识
```

档案和我的话冲突时，以我的当次表述为准，**并且顺手把档案改掉**。

## 5. 输出格式偏好

- 中文回答；代码、命令、报错保持原文。
- 结论先行，过程后置。不要「让我来分析一下」这种垫话。
- 长内容用文件交付，别在聊天里刷屏。
- 不确定就写「不确定」，不要编一个像样的答案。

## 6. 这个仓库不是

- 不是知识剪藏库。**不要往里塞教程、文章全文**，只放「我自己的判断」。
- 不是日记。**会话原文不进公开层**，档案主体保持结构化。
- 不是给人看的作品集。**唯一读者是 AI**——所以写结论、写判断、写偏好，不用写漂亮话。
